Hill Climb gives your team mock connectors, eval scenarios, and a baseline-vs-revision comparison loop. Know your change is safe before you deploy.

The problem

Monday morning

Your agent sends emails via Gmail, creates calendar events, reads Google Drive files, and updates Sheets. A customer reports the agent sent a duplicate email. You fix the system prompt. Push to staging. The email is fixed. But now the calendar connector hallucinates event times. You find out Thursday from another customer.

With Hill Climb

Before pushing, you run hillclimb compare baseline. After your fix, hillclimb compare revision. The report shows: email FIXED, calendar STABLE, sheets STABLE, drive STABLE, 0 regressions. You deploy Monday morning with confidence.

How your team would use it

  1. Install (30 seconds)
    git clone https://github.com/SamuelChien/hillclimb && pip install fastapi uvicorn
  2. Start mocks
    python mock-services/app.py &
    Point your agent's COMPOSIO_BASE_URL at localhost:8081.
  3. Run baseline before your prompt change
    bash demo/compare.sh baseline
  4. Make your change to the system prompt, tool descriptions, or skills
  5. Run revision after your change
    bash demo/compare.sh revision
    Get the verdict: SAFE TO DEPLOY or REGRESSED.
  6. Scan sessions weekly to find new failure patterns
    hillclimb run --since 7d
